Pandamonium / PandaBear / BlackBear 2.0.65 (261) — 2026-10-27

Regression: terminating Bare's worklet thread without closing its Corestores
leaves filesystem locks held by the Android process. A new worklet then reports
ELOCKED for photo uploads and receiving files. The Fold's in-app restart retained
PID 31884; the newly started worklet immediately failed to open media storage.

Proof: the pinned Bare 1.34.1 / Corestore reproduction opens a store on a worker,
terminates and joins the worker, then fails reopening it on the same process with
ELOCKED. Closing the store before termination allows the same reopen to succeed.
Keets test/worklet-lock-worker.js and test/worklet-lock-test.js preserve this proof.

Fix: Keets 1.3.1 parent-only push IPC closes the media swarm and all chat/private
Corestores, drains pending opens and prevents new media opens during shutdown.
Android waits for media-closed-v1 before terminating the worklet. A shared lifecycle
executor serializes service instances and runs the wait off the UI thread. A failed
or timed-out close never authorizes a second storage owner. Existing media keys,
photos, private-transfer pause flags, messages and wallet data are preserved.
