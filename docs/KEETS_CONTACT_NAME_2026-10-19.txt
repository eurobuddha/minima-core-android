Keets unnamed contact repair — 2026-10-19
Scope: shared native bear chat. Pandamonium2.0.5/code200 local candidate.
Public/device demo release remains2.0.0.

Problem
An incoming message created a contact with its public key as the name when the
sender had not chosen a display name. ChatDb.ensureContact used INSERT OR IGNORE
on every later message, so a subsequently received name was never adopted.
The list refreshed but kept reading the old placeholder. The conversation title
also needed refreshing on inbox notifications and when returning to the activity.

Reuse
Read app/src/main/java/com/eurobuddha/minimacore/chat/{ChatDb,ChatDrainer,
ChatSchema,ChatView,ChatThreadActivity,ChatUi}.java and their callers.
Reused maxima-core/src/main/java/com/eurobuddha/maxima/core/MaximaNode.java
storeKeetsContact's established rule: received names fill unnamed contacts only.
Read its ChatEngine onKeetsInbound caller and the standalone implementation at
/Users/eurobuddha/Projects/minima/mds/keetchat/service.js and chatschema.js.
The standalone MDS ensureContact has the same insert-only limitation; its port is
recorded for after the demo. No new protocol or dependency is needed for this fix.

Repair
Conditional SQLite updates fill blank/public-key placeholders while preserving
custom and established names, payment addresses, receipt markers and history.
Database version3 recovers placeholders from the latest valid incoming name
already stored for the same peer. Outgoing messages never supply peer names.
The migration updates existing contacts only and does not create orphan contacts.
The conversation title refreshes on inbox notification and resume. Keets names
such as 0xAlice are no longer confused with the peer's full hexadecimal identity.
Parlons-specific contact display handling is retained.

Protocol limit
Saving a local display name currently writes preferences only. A subsequent
normal outgoing message carries that name. This repair adopts the name when
received; it does not introduce an immediate broadcast of profile edits. Already
named contacts retain their name, matching the existing Parlons rule and preserving
manual aliases. Profile broadcasts and tracking remote names separately from
local aliases would be a separate feature.
