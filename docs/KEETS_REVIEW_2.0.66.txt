Code Review — Keets media-lock repair, 2026-10-27

Summary
Reviewed Android 0d1ea75a (2.0.64) through the 2.0.66 working changes, plus the
entire bundled Keets delta from 7b2a52f (1.2.15) to 9cbf9a1 (1.3.1).
Inspected each changed source/test/config file and callers: MinimaService,
BatteryPolicy, media read/API, private sharing, Bare Kit push/terminate, and
pinned build preparation/verification. Graph query confirmed service/policy links.
The storage-close handshake preserves existing keys, private-transfer state,
chat/Salon separation, API authentication and native dependency versions.
No file protocol, encryption, 100 MB chunking, receipt or payment code changed.

Findings
MAJOR — Timeout could leave media permanently unavailable (fixed)
2.0.65 KeetsWorklet.stopNow removed policy callbacks, sent close-media-v1 and
waited five seconds. A slow close could finish after that timeout, leaving the
worker alive with closed media and no automatic recovery. A new service's start
could similarly be dropped while waiting for the previous owner.
Fix: WorkletLifecycle serializes ownership on the existing lifecycle executor,
retries unconfirmed closure after five seconds, and only starts the latest wanted
service after acknowledgement. Old retries cannot resurrect a stopped/replaced
service. Failed starts retain ownership until their close is confirmed. Native
termination still requires the exact acknowledgement; no force-close fallback.
Six deterministic lifecycle tests cover these paths, including duplicate start.
