Findings under investigation (not yet fixed)
1. MAJOR: application lock checks only unlocked -> locked transitions globally.
   MinimaApplication.onActivityStarted leaves cold-restored integrated activities
   and notification destinations accessible when the process starts locked.
   Only core MainActivity calls LockActivity.redirectIfLocked.
   Proven sources read: host AppLock/LockActivity/BiometricUnlock/VaultCrypto,
   wallet MainActivity.onCreate/onResume and WalletSession, navigation Back callback.
2. MAJOR: external IPC command/file permissions are snapshotted on receipt.
   MinimaReceiver workers check node identity but do not re-read ReceiverDB
   before running queued work. Disable/delete/admin revocation can be bypassed
   by work queued before the change. Integrated DirectNodeApi.Request.begin has
   the reusable final-authorization model.
3. MAJOR: ETH Wallet identifies selected assets and balance entries by symbol.
   TokenStore allows different contract addresses with the same symbol (including
   ETH). MainActivity sends via tokenBySym, so the displayed card can select a
   different contract or native ETH. Need address identity throughout UI/send.
4. MAJOR: ETH Wallet and AtomiX derive the same ethbridge key but use independent
   nonce logic. AtomiX EthTx has a per-address serializer; ETH Wallet reads pending
   and sends with no shared allocator. Review cross-module reuse before adapting.
5. MAJOR candidate: UTXO TxnBuilder accepts incomplete signing/post receipts and
   falls back to its local handle as txpowid. Compare NFT TransactionEvidence,
   TxnBuilder, HistoryDb and NodeApi before deciding minimal compatible reuse.
6. Build: LockActivity.onBackPressed intentionally omits super, causing release
   lint MissingSuperCall. Reuse the existing lifecycle-aware Back dispatcher;
   Back must continue to background the locked task.
