Pandamonium Sweep: automatic oversized-batch recovery — 2026-10-19

Request and source reuse
The user specifically required the standalone APK's automatic recovery when a sweep
hits the TxPoW size limit. Reused apks/wallet/app/src/main/java/com/eurobuddha/wallet/
SweepFlow.java (donor 690e9bc, standalone0.2.23): split a rejected pooled batch in
half, replace that job with both halves, and continue to the reviewed destination.
This batches/consolidates plain inputs into fewer outputs at that destination; it
does not add an intermediate transfer back to the old wallet. Whole state/NFT coins
are never pooled or split. Existing planner limits and exact-state builders remain.

TxPoW generator and Main. Both sync/async oversized cases throw before accessing

This supersedes the claim in WALLET_SWEEP_PORT_2026-10-19.txt that the bundled node's

Changes
NodeLink now delivers a distinct size-rejection callback only for an exact structured
status:false, pending:false txnpost reply with the current attempt's id and the node's
size/max message (size greater than max, max at least65536). Transport error strings,
timeouts, import/basics failures, malformed replies and generic 'too big' cannot enter
this branch. Each publish stage accepts only its first terminal callback.
The initial Sweep submission releases its own durable reservation after this proven
rejection. The saved bytes must still match and there must be no accepted receipt.
Failed persistence retains the reservation and prevents replacement signing. NFT UI
reservations are cleared only if their recorded generation still matches.
A pooled job then uses the donor splitter and continues. Its original signature stays
consumed; smaller jobs use new signatures through the existing authenticated worker.
Single/whole coins are reported and skipped, so they cannot cause a split loop or
alter NFT state. Stop-between-batches and session guards remain active.
Retries of previously unknown submissions still replay identical saved bytes. A size
error on such a retry cannot prove the earlier attempt was never accepted, so it does
not release that reservation or sign replacements. No timeout is treated as failure.
Review, progress and single-coin messages exist in English, Chinese, Russian, Ukrainian.

Code review
MAJOR resolved: the previous integration copied split() but never invoked it, so
recoverable oversized batches became permanently pending instead of continuing.
Reviewed canonical flow/planner/pending records, NodeLink adapter, generated source,
caller guards, tests and localized messages. Kept continuation calls outside the
reservation-write exception handler to avoid advancing twice if a later callback throws.
Verdict: approve this bounded repair after regression/build checks below. The complete
Pandamonium review and standalone parity are still open.

Limits and remaining work
No live sweep, seed change, real signing-counter change or real transaction was used
for validation. Fold UI/stop/review/confirmation and large real collections remain
untested on this candidate. A single coin whose full transaction exceeds the limit
cannot be made smaller by splitting its input list. The prior pending-history and
cross-flow reservation limits remain documented in WALLET_SWEEP_PORT_2026-10-19.txt.
Standalone Sweep already has automatic splitting; its generic error recognition,
timeout-based re-signing and lack of durable retry still need the reviewed safety
parity changes. ETH Wallet parity investigation was interrupted by this user request;
no standalone ETH Wallet files were changed in this checkpoint. Public/device2.0.0
is unchanged. This candidate must not be called a completed full-app review.
