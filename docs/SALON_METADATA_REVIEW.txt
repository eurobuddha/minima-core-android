Salon NFT metadata review — 2026-10-18

Summary
Salon's asset picker and held-edition scan assumed token metadata and token.name
were already JSON objects. Serialized metadata became a JSON label or lost its
cover/base/ext. The adapter reuses NFT Wallet's exact asObject/tokenObject methods,
derived from the MinimaCore wallet balance parser and already reused in Atelier.
Only the two display/enumeration callers are adapted. The original IconResolver,
NftProof edition URL/state-image logic, proof generation and node commands remain.

Sources inspected
app/.../main/views/balance/BalanceAdapter.java and tokens/TokenMeta.java;
integrated/NFTwallet/.../TokenMeta.java and Util.java;
scripts/adapt-pandamonium-token-metadata.py and -atelier-viewer.py;
standalone apks/salon/.../Util.java; integrated Salon MainActivity, Util,
IconResolver, NftProof, IdentityBalance; wallet and Atelier metadata tests and
SalonHoldingsLanguageTest. Core uses Minima JSON; Salon uses org.json, so the
existing NFT Wallet adaptation is copied by the importer rather than adding a
circular dependency from the integrated library to the host application.

Review
No blocking finding in the final change. The parser handles object/string roots,
object/string names and existing token envelopes without mutating node replies.
Outer token IDs remain authoritative; nested metadata does not replace them.
Authored names, image bytes, proof bytes and edition captions remain literal.
Missing names retain Salon's shortened-token-ID fallback. Existing URL aliases,
IPFS resolution, duplicate edition handling and embedded-image precedence remain.
The publication cap still excludes embedded data URIs; local display supports them.
No raw metadata migration or rewriting of existing saved user captions is added.

through the real picker/proof-storage boundary and edition URL assembly. Fixtures

and malformed-JSON names, image aliases, base/ext fallbacks, multilingual selection,

Verdict
Approve this metadata checkpoint. The full Atelier/Salon goal remains active:
