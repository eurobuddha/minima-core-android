Findings fixed
MAJOR: tool dialogs and address callbacks retained mutable selected Coin objects
and read the live selected token later. Changes after review could therefore alter
or invalidate the request. Split/merge/distribution lacked a fresh selection check
before constructing their transactions. Untrack also read mutable IDs on each
successive command, rather than using the IDs accepted by the user.
MINOR: old operation callbacks could clear a newer selection or overwrite a newer
operation's status. Unknown results unnecessarily cleared selection.

Reviewed behavior
Review freezes public coin identity/economics/spendability and captures its token.
Acceptance is single-use, rejects closed activities, validates inputs and compares
the current selection. Async lookup checks run again before posting. Abandoned
distribution lookup cancels its start reservation. Identical refreshed selections
are accepted, while submitted values remain independent copies. Later outcomes
preserve audit/history updates and cannot overwrite a newer review's status or
clear a different selection. Untrack uses frozen IDs with a final ID syntax check.
No real signing, transfer or cointrack command was used for validation.
