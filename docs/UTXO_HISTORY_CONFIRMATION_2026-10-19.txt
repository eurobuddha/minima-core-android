Reuse and changes
Inspected complete UTXO HistoryDb/Row/View, NodeTx, TxnBuilder, NodeApi and relevant
MainActivity lifecycle/callers, standalone equivalents, NFT TransactionEvidence
and its tests, NFT LocalHistory, and core history/txpow command implementation.
Reuse NFT economic matching, strict envelope/identifier parsing, atomic status
updates and minimum three-block inclusion checks. Legacy UTXO rows lack the full
NFT journal, so the adapter checks their saved coin IDs, human amounts, token,
all destinations, output multiplicity, scaling and native burn. Existing valid
TxPoW identifiers constrain matches; ambiguous duplicates remain unresolved.

HistoryRecovery issues only bounded history/txpow reads. It rechecks the current
saved row before atomically saving its confirmed display record. Fresh node
history supplies token deltas; inclusion supplies actual confirmation height.
Close suppresses late callbacks. Existing cache entries cannot authorize success;
late write callbacks cannot downgrade a verified row. A pending-only query avoids
newer error rows hiding older unresolved attempts. Each tick reads up to four
pages, with adaptive page shrinking. Unreadable entries remain unresolved and
are retried on later complete scans.

Database v7 preserves both v6 tables. Previously inferred confirmations/failures
are reopened for validation; real preparation errors are retained. The saved WIP
would have discarded cached history and could claim one receipt for multiple
attempts; both issues were corrected before adoption. Fresh token breakdowns use
human token units. Cached UI rows are invalidated after verified recovery.
