Wallet history pagination review — 2026-10-19
Scope: Pandamonium integrated UTXO Wallet and NFT Wallet history loading.
Local 2.0.3/code198 checkpoint. Fold and public stores remain on verified 2.0.0.

Findings fixed
MAJOR: UTXO used its accumulated database row count as a node offset. A fresh
session with 70 cached rows loaded the first eight and then requested offset70,
skipping the intervening records. Filtered non-transactions also prevented the
cursor advancing. NFT already counted raw rows but retained its previous maximum
cursor across fresh head scans, allowing newly inserted records to be skipped.
MINOR: both empty-list renderers returned before adding Load older, making earlier
transactions unreachable when a page contained only non-transactions.
MAJOR: malformed pages could partially persist; absent economic details became
zero/self transactions in an insert-ignore cache. Both now validate the entire
page before persistence, including each transaction's difference object.
MINOR: the <= height guard suppressed refresh following a rollback. Recording the
callback's current height also marked a block as fetched when the request began
at an earlier height. Both now compare equal heights and record the requested
head-page height. Load older restarts at the head if that height changed.
MINOR: NFT retried offline errors with progressively smaller pages. Reuse UTXO's
explicit oversize-only retry behavior; preserve the same raw offset on failure.
